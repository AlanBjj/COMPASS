# COMPASS

Code and data for **COMPASS: Mitigating Hallucination via Complexity-Aware Adaptive Reasoning**.

COMPASS is a training-free framework that selects a reasoning strategy (plan) for each question and
checks the answer according to its type: a hybrid gate estimates the question's complexity and its need
for external knowledge, a rule-based planner chooses among direct, retrieval, whole-question, and
decomposition plans, and a type-routed consistency layer votes on canonical answers (TRACE) or
cross-checks the question's premise (CPC). Every component runs on the same open model that answers
the question; everything runs offline on local GPUs.

## Layout

| Path | Content |
|---|---|
| `compass/` | the method (`pipeline.py`: plan selection, Algorithm 1; `gate/`, `decompose/`, `solvers/`, `fusion/`, `aggregation/` for TRACE and CPC), the evaluation (`eval/`), and the six baselines (`baselines/`) |
| `prompts/` | every prompt, as plain text |
| `configs/<backbone>/<dataset>.yaml` | COMPASS configs (full method); `configs/<backbone>/baselines/<dataset>.yaml` for the baselines, including the calibrated TARG and DTR thresholds. Generated by `scripts/make_configs.py` |
| `scripts/` | serving, job scheduling, judging, calibration, and the script that computes every table of the paper |
| `human_eval/` | annotation guideline and the three annotators' labels for the judge validation (160 items) |
| `data/` (data archive) | the four benchmarks as used, and the frozen retrieval snapshot with its BM25 index |
| `results/` (data archive) | every judged run reported in the paper |

## 1. Environment and models

* Python 3.11: `pip install -r requirements.txt`.
* vLLM 0.30 for serving, in its own environment.
* Model weights under `$MODELS`: Qwen3-8B, Meta-Llama-3.1-8B-Instruct, Ministral-8B-Instruct-2410,
  Qwen3-32B (judge), and bge-m3 (DTR baseline only).

```bash
bash scripts/serve.sh start qwen3-8b judge   # backbone on GPU 0 (port 8100), judge on GPUs 3-4 (port 8200)
bash scripts/serve.sh start embed            # bge-m3 for DTR (port 8300)
bash scripts/serve.sh status
```

## 2. Data

The benchmarks, the retrieval snapshot, and every judged run are in one archive on the release page
(`COMPASS_data.tar.gz`, 239 MB; its sha256 is in `COMPASS_data.sha256`). Unpack it at the repository
root, which creates `data/` and `results/`:

```bash
curl -LO https://github.com/AlanBjj/COMPASS/releases/download/data/COMPASS_data.tar.gz
tar xzf COMPASS_data.tar.gz
```

The retrieval snapshot
(`data/snapshot_corpus/corpus.jsonl`, 251,454 de-duplicated web snippets with source type and date, and
the BM25 index in `data/snapshot_corpus/bm25/`) is shared by all methods; `MANIFEST.json` records its
counts and sha256. It was built with `scripts/build_snapshot_corpus.py` from web-search results
collected for the benchmark questions. The development split is FreshQA's official development split
(100 questions) and, for the other benchmarks, the first 100 questions after a seeded shuffle (seed 0);
the test split is the rest (`compass/datasets/`).

## 3. Running

```bash
python scripts/make_configs.py               # writes configs/ (already included)

# COMPASS (full method) and one ablation on the test split, three runs, generation only:
python scripts/run_jobs.py --backbone qwen3-8b --split test --methods full no-cpc --reps 1 2 3 \
    --urls http://localhost:8100/v1 --gen-only
# a baseline:
python scripts/run_jobs.py --backbone qwen3-8b --split test --methods B.targ --reps 1 2 3 \
    --urls http://localhost:8100/v1 --gen-only
# judge the generated answers:
python scripts/judge_generated.py results/qwen3-8b/*_gen.json results/qwen3-8b/baselines/*.gen.json
```

A single run is `python -m compass.run --config configs/qwen3-8b/freshqa.yaml --split test --tag test_rep1`
(`--variant <ablation>` for an ablation, `--set gate.tau=0.40` to override a value). The ablations are
`no-trace`, `no-cpc`, `no-implicit-facts`, `no-cpc-on-retrieval`, `no-recency-plan`,
`no-arithmetic-test`, `no-recency-exemption`, and `no-fact-plan` (`compass/run.py`). Sensitivity runs
use the development split, e.g. `--split dev --extra-args "--set gate.tau=0.40" --tag-prefix tau0.40`.

TARG/DTR thresholds: run the `targ_never`/`targ_always` (`dtr_never`/`dtr_always`) branches on the
development split, then `python scripts/calibrate_gate.py --method targ --dir results/qwen3-8b/baselines --rep 1 2 3`.

Every run checkpoints every 100 questions and resumes from its `.partial.json` when restarted.

## 4. Tables and judge validation

```bash
python scripts/paper_tables.py --results results --out paper_tables/   # every table and figure data file of the paper
python scripts/summarize.py --dir results/qwen3-8b --split test        # one-screen overview
python scripts/judge_calibration.py --config configs/qwen3-8b/truthfulqa.yaml   # judge vs. annotators
```

## 5. Result files

`results/<backbone>/compass_<dataset>[_<ablation>]_<split>[_<setting>]_rep<k>.json` (COMPASS) and
`results/<backbone>/baselines/<method>_<dataset>_<split>_r<k>.json` (baselines) hold, per run, the
effective configuration (`meta.effective_config`), every answer with its execution trace (plan, gate
scores, consistency votes or CPC verdicts), the judge's labels, and token counts per role.
